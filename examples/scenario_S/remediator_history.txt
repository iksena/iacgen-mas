### Root Cause Analysis

- **Single error, single root cause.** The only structural failure is `terraform-validate` rejecting `password` on `aws_iam_user_login_profile.governance` (line 286). The AWS provider marks this attribute as **computed-only**: the login-profile password is generated automatically at apply time and cannot be supplied from configuration.
- **No Checkov/Trivy errors are present in this iteration**, so there is nothing to consolidate — but the fix must not reintroduce a plaintext secret to satisfy the original "password from `random_password`" objective. Those two goals are mutually exclusive with this resource type: the provider does not accept a user-supplied password.

This is part of the same logical fix even though only the encryption line is flagged.

### Fix Objectives

1. **Create a customer managed key for the artifacts bucket** as a new `resource "aws_kms_key"` block (e.g. label `artifacts`). This is the object the encryption config will reference; do not introduce any hardcoded key ARNs or account IDs.
